# Corrected fixed and concentrated recovery model

Historical synthetic control: engineering-context-evidence.md and
engineering-calibrated-experiments.md supersede these illustrative sizes as the
CLI default. These runs isolate recovery dispersion, not actual project size.

Recorded on 2026-10-06 for version 0.1.1. This correction implements the user's
workload premise that retained state and reloaded documents are concentrated
near project-specific constants. The numerical constants below remain
illustrative: the user has not provided measured retained/document sizes.

## Model correction

Let L be verbatim old context retained, C generated summary, and D reloaded
documents. The rebuilt state is S=L+C+D. Only C is generated by the compactor
and billed as output; L and D are billed when processed as normal-request input.
The synthetic baseline is L=0, C=2,000, D=12,000. No default H-proportional term remains.

The random normal growth, request intervals, threshold crossing, cache expiry,
and finite end of the task remain unchanged. Fixed recovery therefore does not
replace the entire stochastic model by its means. For small-noise sensitivity,
independent Lognormal C and D with CV 0.05 preserve their absolute means and
remain independent of the compact threshold. This CV is a sensitivity setting,
not a measured parameter.

Preservation targets are capped by available old context only. Documents and
sampled summaries are never tail-clipped. By default the changed mutable prefix
is cold; an explicitly declared unchanged eligible leading boundary inside L
can survive up to its previously warm length. Copying identical content without
a matching prefix boundary is not evidence of cache reuse. Expired boundaries
remain cold.

Prices are unchanged: USD per million tokens input 3, write 3.75, read 0.30,
output 15. Compactor and normal calls use the same Pricing object. This isolates
the recovery correction rather than mixing it with a new model price schedule.

## Experiment design and outputs

Discovery and confirmation each use 4,096 independent trajectories of 400
normal calls, seeds 20261006 and 20261007. The corrected grid is 20k to 80k in
2k steps and paired centered secant step is 2k. All profiles share identical
ordinary growth and gap realizations at a given seed. No-compaction expectations
are identical across these profiles because recovery is not invoked.

| Same means, CV 0.05 | 40k | 13.659710 | 13.643056 to 13.676365 | 34k to 44k, step 2k |

The legacy control uses the original 25k to 150k grid in 5k steps, restored
through --scenario legacy. Its validation mean exactly reproduces the original
baseline result. Explicit old parameters and four-array RandomField constructors
remain supported. Current defaults intentionally change as requested.

The 3.2k summary controls match the legacy summary mean at H=40k, not at every
H; the legacy mean is itself threshold-dependent. They help avoid attributing
every result difference to dispersion, but are not a pure mean-matched
distribution comparison over the entire grid.

## Small-noise versus constant approximation

At the independently selected threshold, paired confirmation differences
(narrow minus fixed) are:

- C mean 2k, h=40k: USD -0.000101; interval -0.004114 to 0.003913.
- C mean 3.2k, h=44k: USD 0.001934; interval -0.002238 to 0.006107.

These intervals lie inside plus/minus 0.01 USD for a 400-call task, conditional
on this model and the declared independent CV 0.05 perturbations. Thus the
constant approximation is practically close for these sensitivity settings.
This is not a guarantee for other sizes, correlated noise, cache survival,
prices, or a real measured workload. The 1% grid regions are exploratory cost
sets, not simultaneous confidence/equivalence regions.

Changing only fixed summary size from 2k to 3.2k shifts the selected grid point
from 40k to 44k under this workload. This is more informative than assigning a
wide arbitrary recovery tail: the core sizes need calibration before a real
threshold recommendation. Do not treat the smaller invoice of a new profile as
an actual client optimization; this is a change in the modeled workload law.

## Reproduction

Use the root .venv and locked uv environment:

```sh
# All generated reports and paired trajectory arrays stay inside .cache.
uv run compaction-lab sweep --replicates 4096 --calls 400 --thresholds 20000:80000:2000 --difference-step 2000 --output .cache/experiments/recovery-fixed
uv run compaction-lab sweep --replicates 4096 --calls 400 --thresholds 20000:80000:2000 --difference-step 2000 --recovery-cv 0.05 --output .cache/experiments/recovery-narrow-005
uv run compaction-lab sweep --replicates 4096 --calls 400 --thresholds 20000:80000:2000 --difference-step 2000 --summary-tokens 3200 --output .cache/experiments/recovery-matched-fixed
uv run compaction-lab sweep --replicates 4096 --calls 400 --thresholds 20000:80000:2000 --difference-step 2000 --summary-tokens 3200 --recovery-cv 0.05 --output .cache/experiments/recovery-matched-narrow
uv run compaction-lab sweep --scenario legacy --replicates 4096 --calls 400 --output .cache/experiments/recovery-legacy
```

Profiles are fully recorded in each sweep.json, with source SHA256
5f8ba3b93da834eb8b5f81cb0146ab93797785def212f1a8042725d22cafe2dc.
Python/package versions and seeds are in the manifests. Raw data is regenerated
and ignored by Git. The local .temp/summarize_recovery.py probe reproduces the
paired small-noise contrasts and writes .cache/experiments/recovery-summary.json.

## Verification and scope

All 75 maintained tests passed, including legacy constructor behavior,
fixed-summary independence from threshold, verbatim retention without output
fees, surviving warm boundary, inability to resurrect expired cache, and
distributed summary marks. Independent focused review also ran the 75 tests.
Wheel and sdist builds succeeded for 0.1.1. The documented transition contract
was updated alongside source.

The simulator still omits hard context capacity, price tiers, actual compaction
latency, a separate compressor-model price schedule, and multiple cache
boundaries/routing. No new architecture was introduced to address those issues.
Next useful inputs are project-specific L/C/D sizes and the actual model rates;
random growth and cache survival can then be calibrated around those constants.
